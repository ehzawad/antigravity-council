# Design

The host owns meaning; the runtime owns execution. Claude reads the conversation and worktree, frames independent questions, resolves the user's model choices to exact live-catalog IDs (when the user names none, it omits `model` so agy's configured default applies; it does not pick one), and reconciles. Python validates contracts, launches children, records evidence, and reports failures. There is no role catalog, vote aggregation, or hidden planner in the runner.

## Module boundaries

| Module | Responsibility |
|---|---|
| `antigravity_council.py` | CLI dispatch and skill/runtime handshake |
| `council_common.py` | Strict data, private storage, capsule parsing, identity and lock primitives |
| `council_models.py` | Native provider check, metadata probes, catalog parsing, exact model membership |
| `council_policy.py` | Content-addressed worker profiles (`full` default, restricted `read`/`write`/`execute` opt-ins), session-only full-access settings, restricted-writer validation |
| `council_protocol.py` | Antigravity stdin/event contract, terminal validation, diagnostic classification |
| `council_runtime.py` | Per-role subprocesses, locks, continuation, retries, streams, the full roles' self-verification turn, and reply persistence |
| `council_lifecycle.py` | Run creation, input binding, supervisor, durable status, follow/collect/cancel/reap |

No external service, database, API key manager, or Python dependency is required. Separate modules make vendor protocol changes reviewable without touching host role synthesis. A microservice deployment would add network and authentication surfaces without helping this local plugin's job.

## Execution and state

Preparation records the exact canonical workspace, host session, task key, concurrency, restricted writer (if any), and timeout policy. The host authors roles/context. Preflight validates files, authority, installed profiles, models, required CLI flags, and capsule. Launch repeats discovery, claims a directory exactly once, hashes the inputs, and transfers an open kernel lock descriptor to a child in its own session. The child publishes its own birth identity and verifies the hash before dispatch.

Each role has a separate CLI process and a separately keyed saved conversation. Its stdin receives one JSON user message per turn and is closed after the last one; agy runs one turn per stdin message, emits one `init` per process and one `result` per turn, and exits when stdin closes (observed live). Both output streams are consumed concurrently. A role without `access` runs as `full`: it launches with `--dangerously-skip-permissions`, an explicit `--mode accept-edits` (agy >= 1.5.7 otherwise starts headless runs in Auto mode, which turns the no-network terminal sandbox on), and session-only `--settings` that disable the terminal sandbox, allow non-workspace access, and set tool permission to `always-proceed`; nothing is written to `settings.json`. The full profile lists agy's own harness tools (subagents, workflows, scheduling), sets `commandExecutionPolicy: eager` and `inheritMcp: true` (an undocumented field), and has no `mcpServers`, `skills`, or `plugins` lists. Live, tools from the user's installed agy plugins (MCP servers) and the user's custom agents were visible to full workers, but plugin MCP tools were also visible under an earlier profile with `mcpServers: []` and no `inheritMcp`, so the field's effect is unproven; skills were not verified. Those harness tools were confirmed on agy 1.5.12, the minimum for full access: an older CLI lacking one fails full roles at startup with "profile tools absent from this agy registry". A full role gets no `--add-dir`: in agy 1.5.12 an added run directory became the default command working directory, so commands ran outside the project (observed live). Its prompt lists the run directory by absolute path and tells it to run commands from the workspace root. Restricted roles keep empty extension lists and still get the run directory through `--add-dir`. Restricted write/execute roles keep `--mode accept-edits`, and execute adds `--sandbox`.

By default every full role works in two turns on one conversation; `prepare --no-verify-turn` (`verify_turn: false` in `launch.json`) runs full roles single-turn instead. After turn one returns SUCCESS with a nonempty response, the runner sends a forced self-verification message on the same stream. It tells the worker to treat its draft as someone else's, re-check every claim against live evidence (re-read lines, inspect the diff, re-run tests), use its own subagents to try to refute the most consequential claims (briefed with the claim and evidence only), confirm that a cited defect actually exists before accepting a refutation, fix or retract and repeat until nothing new turns up, report honestly, and write a complete final report that replaces the draft. The reply's `response` is that final report; `draft_response` keeps the turn-one draft whenever a verification turn was used, and `verification_turn` (`completed`, `failed`, `not-run`, or `off`; null for restricted roles), `verification_turn_completed`, and `turns_completed` record what happened. The markdown reply shows `verification turn: completed|failed|off`. A completed verification turn means the worker re-checked its work, not that the answer is correct. If turn one fails, no verification turn is sent, and it is never sent after the stream ended, failed its audit, or had no validated init. If the verification turn fails, the role fails and `response` carries the unverified draft with a warning saying so. If the process fails after a completed verification turn (nonzero exit, stall, or a late event), the role still fails, with a warning, but `response` keeps the verified final report. Restricted roles stay single-turn. The report format stays free-form, and a verification turn may improve the evidence but never replaces the host's independent check.

Live, the verification turn worked mechanically and once spawned its own skeptic subagent, but no live run has shown it changing an answer. It costs time and quota: a trivial task went from 88s to 211s, and three parallel high-effort workers plus their subagents hit the account's quota, so their verification turns failed. Size parallel councils to quota.

The parser accepts the documented event structure and ignores extra fields. It fails a role on malformed events or a wrong `init.agent` or pinned `init.model`. Restricted roles also fail on nested subagent activity and on any tool step outside their profile. agy 1.5.x reports some steps under new names; only observed aliases map back to profile tools (`read_file` to `view_file`, `write_file` to `write_to_file`, `edit_file` to `replace_file_content`), which also keeps a restricted writer from failing on its first write. A full role must report `init.permission_mode` `always-proceed`, or it fails as a protocol error instead of running half-restricted. A full role's agy subagent use is recorded once as a reply warning ("worker used agy subagents; their work is part of this reply's evidence") and makes the role non-replayable; its tool step outside its profile list is likewise recorded once as a warning, not treated as failure. Actions agy reports in `result.denied_actions` are kept in the reply as coverage warnings. A later turn's result must follow a new `user_input` step, keep the stream's `conversation_id`, and advance `num_turns`; after a result, only the next turn's `user_input` may come first. A successful return requires a validated init, a nonempty SUCCESS result for every turn sent, and process exit 0.

A settled reply is written before its role-completed event. Results remain useful when a sibling fails or the host disconnects. Final reports state transport status and leave semantic acceptance to Claude. A response timeout and an output-inactivity watchdog prevent a worker from silently persisting forever under default settings. `--print-timeout` budgets each turn: agy applies it per turn (observed live: a second turn finished after the limit had passed for the process as a whole), so the runner passes the configured value unchanged (60m stays 60m), and its own process watchdog allows turns times the timeout plus 5 seconds. On cancel or timeout the runner also walks agy's descendants and kills their process groups, because agy starts each shell command in its own group; before this release a cancelled worker's command survived as an orphan, and a live cancel after the fix left none. A tool that double-forks into an unrelated session before cleanup can still escape. A dead saved conversation (`stale-session`) is dropped for every role, and any role, full included, restarts fresh once when the error came before any tool work. Otherwise only restricted read roles are retried automatically (one transient retry and one headless permission-abort retry); full roles and restricted mutators are never replayed because they may have edited files, run commands, or used subagents.

Full-only and read-only councils take a shared workspace lock, so several full roles, and several such councils, may edit one worktree at once with no writer limit. A council with a restricted write/execute role, which must be named with `--writer`, takes the lock exclusively.

The event journal is informational; lifecycle decisions use the supervisor lock and process birth identity. Lock/process reads are non-atomic, so the follower briefly reobserves an inconsistent snapshot rather than announcing completion or immediately failing. Persistent uncertainty remains explicit and never authorizes a signal.

## Deliberate differences from Codex Council

This is not an exhaustive feature-for-feature port. It retains host-defined roles, private staged context, independent persisted conversations, bounded fan-out, detached supervision, early replies, final reconciliation, and conservative recovery.

Antigravity-specific differences include its `event`-based wire protocol, streaming stdin, explicit per-worker native timeout, exact catalog variant IDs for a requested effort (the optional `effort` field is sent as agy's `--effort` only for roles that omit `model`, since agy 1.5.12 rejects `--effort` beside a catalog variant ID and `parse_roles` refuses the pair; agy's init does not report effort, so whether it applied it is unobservable), custom-agent profiles, requested-versus-CLI-reported model checks, and treatment of soft permission denials and `denied_actions` as coverage gaps. It does not use Codex app-server RPC, Codex JSONL `type` records, or native Codex configuration inheritance. Full roles do bypass permission prompts and the terminal sandbox by default, through agy's own documented flags and session-only settings rather than Codex's.

The Intent Capsule and the restricted roles' explicit single-writer gate draw on Cursor Cult's design. This implementation additionally binds a capsule digest across a stable task key and includes model, effort (when set), and access in session identity. An expressly requested new model or effort therefore starts an independent thread.

The self-verification turn draws on two DeepSeek sources. DeepSeekMath-V2 ([arXiv 2511.22570](https://arxiv.org/abs/2511.22570)) suggested honest self-analysis, refining until a check finds nothing new, and meta-verification: confirming that an issue a verifier raises actually exists before acting on it. The same meta-verification step is in the host's reconciliation: before a refutation overturns a worker claim, the host confirms the cited defect exists. DeepSeek's super-agent research prototype ([dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)), whose notes report that an agent merely allowed a subagent tool did not call it, is why the verification turn and its delegation are forced rather than merely permitted. These inspired the design; nothing is copied from either.

## Non-goals and known gaps

No council-managed peer messaging or subagent trees (a full worker may use agy's own subagents; a restricted worker may not), automatic worktree creation, merge coordination between concurrent full-role editors, model ranking or preference, quota bypass, fallback model hopping, cloud service, or guaranteed host push notifications. No generic SDK abstraction is claimed. No automatic run retention or live provider validation occurs during installation. Full access, process groups, CLI tool profiles, and the workspace lock are not an OS sandbox or a hostile same-user security boundary.

Work a full worker starts through agy's `schedule`, `run_workflow`, or `manage_task` that agy keeps outside the process tree may outlive the council; cancel and reap cannot reach it (in live runs, `schedule` was used only as an in-turn wake-up timer and was cancelled early). Workers have no browser tools: agy 1.5.12 refuses `browser_*`, `browser_subagent`, and several other names its `init.tools` lists (among them `call_mcp_tool`, `read_resource`, and `sed_file`) when a custom agent names them ("not found in registry"). Browser-like work goes through the shell. Plugin MCP tools were visible to full workers, but whether `inheritMcp` is what provides them is unproven. On 1.5.12 the full profile's `read_url_content`, `grep_search`, `list_dir`, `find_by_name`, `command_status`, and `send_command_input` were not exposed to the model; URL fetching worked with curl in the unsandboxed shell.

Current test fixtures validate this implementation's interpretation of the documented contract. They cannot prove that a newly released `agy` binary implements the contract identically. The opt-in billable smoke test (`scripts/live_smoke.py`, full access by default, where it checks from turn one's stream steps and the filesystem: transport ok, the canary in the reply, `permission_mode` `always-proceed`, a completed verification turn, a shell command that wrote `shell-marker.txt`, file tools that wrote then edited `edit-marker.txt`, HTTP 200 from the shell, a `search_web` step, the page in a shell or URL-tool output (a search snippet does not count), a completed agy subagent, and no denied actions; `--restricted` runs the read-only canary) and a real Claude plugin validation remain the final local acceptance gates; live results are recorded in [docs/VALIDATION.md](docs/VALIDATION.md).
