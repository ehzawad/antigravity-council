# Runtime operations

`setup` writes only the four named worker profiles (`full`, `read`, `write`, `execute`) into `~/.gemini/config/agents`; it is idempotent and changes no settings or credentials, and a missing profile stops preflight with an instruction to run it. Profile names carry a content hash, so a release that changes a profile needs `setup` again; 1.0.1 added `inheritMcp: false` to the three restricted profiles, renaming them, and left `full` unchanged; 1.1.0 changes no profile. 1.1.0 is skill contract 3: every command takes global `--skill-contract 3` before the subcommand, a mismatch is refused (update the plugin; do not change the number to bypass it), and a run directory prepared under an older contract is refused as stale, so prepare a new one. `prepare` creates a private durable run and invalid-until-filled input templates, and records `--workspace` (`auto`, `shared`, `per-role`, or `live`; default `auto`). `discover` performs metadata probes. `check` validates without starting workers and reports the effective workspace mode. `start` rechecks metadata, exclusively claims the directory, creates the council workspace, and starts a detached supervisor. `run` is the attached equivalent for direct CLI use. `diff` and `land` bring a council workspace's result back after the run (below).

One launch owns one directory. Never reuse a directory after either launch path has claimed it, including after failure. The root lives under `$XDG_STATE_HOME/antigravity-council`, or `~/.local/state/antigravity-council`. No automatic cleanup occurs, of run directories, worktrees, or branches.

Files: `launch.json`, `roles.json`, `context.md`, `model-snapshot.json`, `launch-plan.json`, `supervisor.lock`, `supervisor.json`, `state.json`, `events.ndjson`, `workspace.json`, `logs/`, `replies/`, and final `report.json`/`report.md`, plus `settings-<role>.json` for each restricted role, `private.git` for a non-git project, and, after `diff` and `land`, `diffs.json`, `<unit>.patch`, and `landed-<unit>.json`. Detached stdout/stderr go to `err.log`. Raw worker streams go to per-attempt files; fields may contain private project data. Files the runner writes are 0600 and run directories 0700; git's own files inside `private.git` follow the umask, within the 0700 run directory.

`status` combines the immutable lock-file identity, lock ownership, and process birth identity. `follow` emits sequenced JSON events and a final verified-end record only after the supervisor has ended. Inconsistent snapshots are retried briefly; persistent uncertainty exits 4 without claiming completion. `follow --after-sequence N` reconnects. `follow --timeout S` stops the watcher only, returning 5.

`collect` refuses a still-running supervisor. `collect --partial` explicitly returns incomplete evidence. `cancel` signals a verified supervisor and waits for it to settle; `cancel --force` may kill that same identity if graceful cancellation fails. `reap` only targets recorded surviving worker groups after the supervisor is verified gone. It refuses an active or unknown supervisor. agy starts each shell command in its own process group; before 1.0.0 a cancelled worker's command survived as an orphan (observed live). On cancellation or timeout the runner now walks agy's live descendants and kills their process groups too, and no command survived a live cancel after that change. A tool that double-forks into an unrelated session before cleanup can still escape; use OS containment for stronger guarantees. Work a full worker starts through agy (`schedule`, `run_workflow`, `manage_task`) that agy keeps outside the process tree may outlive the council, and `cancel` and `reap` cannot reach it (in live runs, `schedule` was used only as an in-turn wake-up timer and was cancelled early).

Where workers work is chosen by how the roles relate. `auto` gives a council with any role whose access is not `read` one shared workspace (unit `council`), for roles building one change together; a council of only restricted `read` roles works in the user's tree. `shared` asks for that one workspace explicitly. `per-role` gives each role whose access is not `read` its own workspace from the same snapshot, for separate or competing changes, while `read` roles run in the user's tree; it is refused when no role can change files. `live` is the user's tree, the behavior before 1.1.0. `status` shows the workspace record. Each worker's prompt says whether its workspace is shared or its own and tells it to make every change there, not in the user's tree; that is an instruction, not an isolation boundary.

Every workspace is a git worktree on branch `antigravity-council-runs/<run-id>/<unit>` at `worktrees/<run-id>/<unit>` under the state root, checked out from a snapshot commit of exactly what the user sees. The snapshot is built with a temporary index (a copy of the user's index when the project is a git repository, so force-added ignored files are kept) plus `git add -A`, `write-tree`, and `commit-tree`; the user's index is never touched. Untracked files that are not ignored are included; ignored files (`.env`, build output) are not, and full workers can read them in the user's tree by absolute path. A repository with no commits uses its own object store and a parentless snapshot. A non-git folder gets a private bare repository, `private.git`, in the run directory; nothing is copied into the project. Submodules are empty in the workspace. Creation is refused when the state root lies inside the project, and if it fails part way, the worktrees and branches it made are removed. Every git run drops all `GIT_*` environment variables and disables hooks (`core.hooksPath=/dev/null`, `core.fsmonitor=false`), and comparisons use plumbing (`diff-index`, `diff-tree`) with `--no-textconv --no-ext-diff --no-color` and explicit `a/` and `b/` prefixes, so the user's diff settings cannot distort snapshots or patches.

`diff` and `land` need a verified-ended supervisor and no recorded worker process alive (after an aborted run, `reap` first); a `live` run has nothing to diff or land. `diff <run_dir> [--role ID]` commits the workspace's changes on its branch (it refuses if the worktree is not on that branch), records that exact result in `diffs.json`, writes `<unit>.patch` from the snapshot to the result (so the user's own starting changes are excluded), and returns `files`, `not_landable` (submodule changes), `ignored_not_landed` (`.gitignore`'d files the workers created, which never land), and `looks_generated` (caches, bytecode, build output: remove them in the workspace and run `diff` again, since `land` takes the whole result). For a per-role council, `diff` without `--role` returns every unit.

`land <run_dir> [--role ID]` (per-role councils require `--role`) applies exactly the result `diff` recorded, all or nothing. It refuses without a prior `diff`; if the workspace changed after `diff` (HEAD differs or there are uncommitted changes); if the branch no longer descends from the snapshot; if the result changes a submodule; if any path the council touched differs in the user's tree from the snapshot (content as git hashes it, mode, or type) or has a parent that is a symlink or not a directory; while the run is not verified ended or a recorded worker process is alive; and a second time for the same unit. Because the first landing changes the user's tree, a competing per-role result that touches the same files is then refused too. It copies originals aside into `land-backup-<unit>/`, deletes, removes emptied directories, writes through a temporary index with `checkout-index` (filters apply; the user's index is untouched), and restores everything if a write fails; a backup left by an unfinished land blocks the next one until inspected. A refusal for user changes points to the patch and the workspace and warns that merging the branch would also bring its snapshot of the user's earlier work. Branches and worktrees are kept, and the output says how to remove them. Landing changes only the working tree; the host never commits, pushes, or merges unless asked.

Limits: case-only renames cannot land on case-insensitive file systems; empty directories are not tracked; absolute symlinks inside the project still point at the user's tree; local edits hidden by assume-unchanged or skip-worktree are not in the snapshot, nor are nested untracked git repositories; a non-git folder with no `.gitignore` is snapshotted whole, which is slow for huge trees; and each launch gets a fresh workspace from the user's current tree, so land first if the next round should build on this one. None of this is an OS isolation boundary: full workers can reach the user's tree by absolute path.

Live on agy 1.5.12: a shared worktree in a git repository with uncommitted and untracked work let a worker fix a bug there, `diff` listed only its file, `land` applied it, the test passed in the user's tree, the user's edit was kept, and the index was untouched; per-role with two competing fixes got separate worktrees, the winner landed, and the second `land` was refused (the workers' test runs had produced `__pycache__` files that the diff listed and that landed with the winner, which is why `looks_generated` exists); a plain folder was fixed and landed through a private repository, with no `.git` left in the project.

Exit codes: 0 all roles supplied usable terminal results; 3 some did; 1 all failed or supervisor failed; 2 usage, staging, model, or capability preflight error, or a `diff`/`land` refusal; 130 cancellation. Follower-only 4 means uncertain liveness and 5 means its own timeout. Read the report, not just an exit code. Tool denials are coverage gaps, including any actions agy reports in `result.denied_actions` (kept in the reply as `denied_actions` and raised as a warning). Replies also record `permission_mode`, `effort`, `verification_turn` (`completed`, `failed`, `not-run`, or `off`; null for restricted roles), `verification_turn_completed`, `turns_completed`, and `draft_response`.

Model sessions are bound to project + host session + task + role + model + profile, plus effort when a role sets one. The project is the user's, not the council workspace, so a resumed conversation may remember edits that were not landed and are not in the new workspace. A dead saved conversation (stale session) is dropped for every role, and any role, full included, restarts fresh once with a continuity-lost warning when the error came before any tool work or undecodable event. Otherwise full roles are never replayed automatically, since they may have edited files, run commands, or used agy subagents; restricted `write`/`execute` roles never auto-replay either. Only a restricted `read` role keeps two more one-time retries: a retryable transient error may retry if no tool work or undecodable event was observed, and a turn that headless mode aborts with an empty response after an out-of-workspace path denial restarts fresh with an explicit path note, because its read/search tools cannot repeat a side effect. No exactly-once claim is made.

Concurrency defaults to six active roles. Full roles have no writer limit: several may edit the same workspace at once (live, four full roles fixing four different functions of one file at the same time all landed their fixes; edits to the same lines can still conflict). The workspace lock, keyed on the user's project, is shared unless the council has a restricted `write`/`execute` role, which takes it exclusively and so excludes other plugin councils on that project; full-only and read-only councils share it and are not serialized against each other. Role locks preserve continuity. Locks do not coordinate full roles' edits with each other or with other editors, and every role in a shared workspace or the user's tree observes a moving tree.

Worker response timeout defaults to 60m per turn. The runner passes the configured `--print-timeout` to agy unchanged (60m stays 60m), and agy applies it per turn (observed on 1.5.12: a second turn finished after the limit had passed for the process as a whole). The runner's own process watchdog allows turns × timeout + 5s. Inactivity watchdog 1,800s, advisory heartbeat 300s, internal state tick at most 15s. `--stall-seconds 0` disables only inactivity checks. This plugin does not claim to disable Antigravity's native timeout. Per-event output bound is 32 MiB; failures are explicit. Stderr diagnostics are tailed in summaries and fully retained in private raw logs.

Full access is the default (`access` omitted or `full`) and is the configured choice, not a per-run authorization; the host still asks the user before commits, pushes, deploys, publishing, or expanding scope. A full role runs profile `agc-full-*` with `--dangerously-skip-permissions`, `--mode accept-edits`, and `--settings '{"allowNonWorkspaceAccess":true,"enableTerminalSandbox":false,"toolPermission":"always-proceed"}'`, and no `--sandbox` or `--add-dir`. The explicit mode displaces the headless Auto default of agy 1.5.7 and later, which turns on the terminal sandbox, where commands have no network access by default. `--settings` lasts for that session only; `settings.json` is not written. Full roles get no `--add-dir` because, observed live on 1.5.12, agy used an added run directory as the default command working directory, so commands ran outside the project; a full role reads the run directory by the absolute path its prompt lists, and the prompt tells it to run commands from the workspace root.

The full profile gives the worker agy's own harness. It lists file read/edit/search tools, `run_command` with `commandExecutionPolicy: eager` plus its follow-up tools, `notebook_edit`, `search_web`, `read_url_content`, agy subagents (`define_subagent`, `invoke_subagent`, `manage_subagents`, `send_message`, `wait`), `run_workflow`, `schedule`, and `manage_task`. It sets `inheritMcp: true` (an undocumented field) and has no `mcpServers`, `skills`, or `plugins` lists. agy 1.5.12 refuses browser tools in a custom agent ("not found in registry": `browser_*`, `browser_subagent`, and also `call_mcp_tool`, `list_resources`, `read_resource`, `sed_file`, `wait_5_seconds`, `manage_inbox`, and `notebook_execution`) even though its `init.tools` lists them, so workers have no browser tools; browser-like work goes through the shell. Under the full profile on 1.5.12, the model saw `run_command`, `manage_task`, `read_file`, `write_file`, `edit_file`, `search_web`, `define_subagent`, `invoke_subagent`, `manage_subagents`, `send_message`, `run_workflow`, and `schedule`, plus tools from the user's installed agy plugins (MCP servers) and the user's custom agents, and a full worker successfully called a plugin MCP tool. Inheriting MCP is agy's default (a profile with no `inheritMcp` key and no lists also made the call); `mcpServers: []` alone does not switch it off, and `inheritMcp: false` does. Workers listed the user's plugin skills under every profile tried, including one with `skills: []` and `plugins: []` (model self-report, not a tool call), so skills appear to reach workers regardless of those lists; that is observed, not guaranteed (restricted roles are blocked from loading them; see below). `read_url_content`, `command_status`, `send_command_input`, `grep_search`, `list_dir`, and `find_by_name` stayed unexposed, and URL fetching worked with `curl` in the unsandboxed shell. A full role can read and edit any file, run any command with the user's network, search the web, and fetch URLs without prompts. Preflight requires the installed CLI to advertise `--dangerously-skip-permissions`, `--mode`, and `--settings` for full roles, and `--effort` for a role that sets effort. Full access needs agy 1.5.12 or later, the version the full profile's harness tools were confirmed on; an older CLI that lacks one of them fails full roles at startup with `profile tools absent from this agy registry`.

Full access is not an OS sandbox, and tool lists are agy's tool selection, not a security boundary. Workers run with the user's OS account and network; the user's own deny/ask rules, agy's system command denylist, and enterprise admin policy still apply. Each full role must report `init.permission_mode` as `always-proceed`; anything else (for example, an admin policy that keeps review on) fails the role as a protocol error. A full role's tool step named outside its profile list is recorded once as a warning, not fatal. A full role may use agy subagents: `subagent_info` in the stream is recorded as a reply warning ("worker used agy subagents; their work is part of this reply's evidence") and marks the attempt non-replayable. Subagent activity still fails a restricted role. `init.agent` and a pinned `init.model` are checked for every role.

Each full role runs two turns on one stream-json conversation by default; `prepare --no-verify-turn` (`launch.json` `verify_turn: false`) runs full roles single-turn with `verification_turn: "off"`. agy runs one turn per stdin message, emits one `init` per process and one `result` per turn, and exits when stdin closes (observed live). After turn one ends `SUCCESS` with a non-empty response, the runner sends a second user message, the forced self-verification turn. It is never sent after the stream ended, failed its audit, or had no validated `init`. A later turn's result must follow a new `user_input` step, keep the stream's `conversation_id`, and advance `num_turns`; after a result, only the next turn's `user_input` may come first. The verification prompt tells the worker to treat its draft as someone else's, re-check every claim against live evidence (re-read the lines, inspect the diff, re-run the tests), use its own subagents to try to refute the most consequential claims (briefed with the claim and its evidence only), confirm that a cited defect actually exists before accepting a refutation, fix or retract and repeat until nothing new turns up, report honestly, and write a complete final report that replaces the draft. The reply's `response` is that final report, `draft_response` keeps the turn-one draft whenever a verification turn was used, `verification_turn` is `completed`, `failed`, `not-run`, or `off` (`verification_turn_completed` gives the same answer as a boolean), `turns_completed` counts successful turns, and the reply markdown shows `verification turn: completed`, `failed`, `not-run`, or `off`. A completed verification turn means the worker re-checked its work, not that the answer is correct. If turn one fails, no verification turn is sent. If the verification turn fails, the role fails and `response` carries the unverified turn-one draft with a warning saying so. If the process fails after a completed verification turn (nonzero exit, stall, or a late event), `response` keeps the verified final report and the role still fails, with a warning. The report format stays free-form. Restricted roles stay single-turn (`verification_turn` is null).

Live, the verification turn worked mechanically and once spawned its own skeptic subagent, but no live run has shown it changing an answer. It costs time and quota: a trivial task went from 88s to 211s, and three parallel high-effort workers plus their subagents hit the account's quota, so their verification turns failed. Size parallel councils to the user's quota.

The restricted profiles are explicit opt-ins: `read` has only local read/search tools and is fenced to the workspace and run directory; `write` adds file tools; `execute` adds shell and requests the vendor sandbox. They get the run directory through `--add-dir`, set `inheritMcp: false` (which is what keeps MCP tools out; with only `mcpServers: []`, a 1.0.0 restricted reader successfully called a plugin MCP tool) plus empty `mcpServers`, `skills`, and `plugins`, and have no subagents. They still see skill names (see above) but cannot load a skill. agy 1.5.12 has no switch that removes skills (profile lists, `--disable-slash-commands`, and `pluginsDisabled` were tried), and a worker loads one by reading its `SKILL.md`, so each restricted role's session settings deny `read_file(<dir>)` on `~/.gemini/config/plugins`, `~/.gemini/config/skills`, `~/.gemini/antigravity-cli/skills`, `~/.gemini/skills`, and the project's and workspace's `.agents/skills` and `.agent/skills`. Whether `--settings` permissions replace or merge with `settings.json` is not documented, so the user's own `allow`, `ask`, and `deny` rules from `~/.gemini/antigravity-cli/settings.json` are merged in; if that file exists but cannot be parsed, restricted roles fail closed rather than drop those rules. The settings are written to a private 0600 file, `settings-<role>.json`, in the run directory and passed as the `--settings` path (agy 1.5.12 accepts a file path; verified live), so the user's rules are not on the command line. Live on 1.5.12, a restricted role's read of a plugin `SKILL.md` was refused and the role continued. Plugin hooks still run. They keep the strict per-profile tool allowlist; a restricted role that calls an MCP tool fails that audit, but only after the call ran. agy reports some steps under new names, so the observed step names `read_file`, `write_file`, and `edit_file` count as `view_file`, `write_to_file`, and `replace_file_content` (observed live), which also keeps a restricted writer from failing on its first write. At most one restricted `write`/`execute` role is allowed, named with an exact `--writer`; its prompt says it is the only restricted writer and that full-access workers, if any, may also edit files. A restricted executor runs with `--sandbox`, `--mode accept-edits`, and session settings that add `"toolPermission":"proceed-in-sandbox"` to those deny rules, so headless agy runs its commands in the terminal sandbox without a prompt or network (live on 1.5.12: `init.permission_mode` was `proceed-in-sandbox`, a `python3` command ran, and `curl` to an external site got HTTP 403 from the sandbox network proxy). Through 1.0.0 it had no `--settings`, and headless agy denied every command it tried, so it could edit files but not run commands, and failed. Preflight requires the CLI to advertise `--settings` for every restricted role. The terminal sandbox is vendor behavior, not containment the runner provides. `--unrestricted-shell` remains a legacy option that adds the bypass flag to that restricted executor in place of `proceed-in-sandbox` (its settings keep the skill deny rules); the host must not choose it simply to avoid a denial.
