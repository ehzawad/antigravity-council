# Source contract ledger

Reviewed against official public documentation on **November 20, 2026**, with the installed `agy` 1.5.12 `--help` and `agy changelog`. Differences between the two are listed in [RECONCILIATION.md](RECONCILIATION.md). URLs are live and may change after that date. The implementation refuses missing capabilities rather than claiming compatibility with every historic CLI version. Full access needs `agy` 1.5.12 or later, the version the full profile's harness tools were confirmed on; an older CLI that lacks one fails full roles at startup with "profile tools absent from this agy registry". The out-of-workspace bypass behavior it relies on dates from 1.5.2.

| Source | Contract used |
|---|---|
| [CLI headless mode](https://antigravity.google/docs/cli/headless/) | Streaming stdin user messages, `event` envelopes, explicit conversation resume, model/agent/effort pins, terminal states, cumulative counters, native response timeout (`0s` means no limit; the runner always passes a positive value unchanged, and agy 1.5.12 applied it per turn). A full role's second, self-verification message (skipped under `--no-verify-turn`) goes on the same stdin stream; one turn per message, one `init` per process, one `result` per turn, and exit when stdin closes were observed live on 1.5.12. `init.permission_mode` is `request-review` by default and `always-proceed` under `--dangerously-skip-permissions`; a full role that does not report `always-proceed` fails |
| [CLI reference: command-line flags](https://antigravity.google/docs/cli/reference/#command-line-flags) | `--effort` (low through max, depending on the model), `--mode` (`accept-edits`, `auto`, `plan`), `--sandbox`, `--dangerously-skip-permissions` (auto-approve all tool permission requests), `--add-dir`, `--agent`. `--settings` is not in this table |
| [CLI reference: settings.json keys](https://antigravity.google/docs/cli/reference/#configuration-keys-settingsjson) | `enableTerminalSandbox` boolean, default `false`; `allowNonWorkspaceAccess` boolean, default `false`; `toolPermission` is `request-review` (default), `proceed-in-sandbox`, `always-proceed`, or `strict`, and deny rules apply in every mode. `agentMode` defaults to Auto where available since 1.5.7 |
| [Agent settings](https://antigravity.google/docs/agent-settings/) | Auto mode turns the terminal sandbox on; `always-proceed` is also activated by `--dangerously-skip-permissions` |
| [CLI execution modes](https://antigravity.google/docs/cli/modes/) | `--mode accept-edits`, passed explicitly so a headless run does not start in Auto; plan mode is not treated as a security boundary |
| [Available models](https://antigravity.google/docs/models/) | Availability depends on product/plan and changes often; local metadata and inference are distinct checks |
| [Enterprise model configuration](https://antigravity.google/docs/enterprise/) | Variant identifiers encode effort choices, and a base ID can take `--effort`; background coordination models can differ from the requested reasoning model |
| [Reasoning effort](https://antigravity.google/docs/cli/commands/effort/) | Effort is model-dependent, and `--effort` applies only to the current invocation. Catalog variant IDs already encode effort, so this adapter meets a requested effort by selecting the variant ID. It sends `--effort` only from the optional `effort` field of a role that omits `model`: agy 1.5.12 rejects `--effort` beside a catalog variant ID (`--model <id> conflicts with --effort=<level>`). agy's `init` does not report effort, so whether it applied one is unobservable |
| [Custom agents](https://antigravity.google/docs/subagents/) | Global Markdown profiles, explicit tool lists, main-agent selection, and optional extensions (`mcpServers`, `skills`, `plugins`, each defaulting to empty; restricted profiles list them empty). The frontmatter table lists `commandExecutionPolicy` values `off`, `auto`, `eager`, and `sandbox` (default `sandbox`) without defining them, so the full profile's `eager` rests on live observation, not documented semantics. The table has no `inheritMcp` row. The full profile sets `inheritMcp: true` and omits the extension lists. On 1.5.12, tools from the user's installed agy plugins (MCP servers) and the user's custom agents appeared in full workers' model-visible tool list, but plugin MCP tools also appeared under an earlier profile with `mcpServers: []` and no `inheritMcp`, so the field's effect is unproven; skills were not verified. The page gives no list of valid tool names and warns that an unmapped name may hang the subagent. On 1.5.12 a name missing from agy's registry was refused with "not found in registry", including the browser tools that `init.tools` names, and some tools reach the model under other names (`read_file`, `write_file`, `edit_file`), which the runner maps back only as observed |
| [Terminal sandbox](https://antigravity.google/docs/sandbox/) | `--sandbox` requests session-level terminal isolation for restricted execute roles; full roles pass no `--sandbox` and turn `enableTerminalSandbox` off for the session. Neither is a Python-enforced security boundary |
| [Permissions](https://antigravity.google/docs/permissions/) | CLI operator policies; allow, deny, and ask rules layer on top of the preset and take precedence; `strict` and `always-proceed` (`--dangerously-skip-permissions`) override Auto |
| [Changelog: CLI 1.5.2](https://antigravity.google/docs/changelog/#rel-cli-1.5.2) | Under `--dangerously-skip-permissions`, reads and writes outside the workspace go through without a prompt, and headless `-p` runs no longer wait on any remaining interaction; explicit deny rules, the system command denylist (the web page calls it the built-in list of protected commands), and Gemini Enterprise admin review still apply |
| [Changelog: CLI 1.5.7](https://antigravity.google/docs/changelog/#rel-cli-1.5.7) | Sessions with no saved mode, including headless `-p` runs, start in Auto wherever Auto is available |
| [Changelog: CLI 1.5.8](https://antigravity.google/docs/changelog/#rel-cli-1.5.8) | Mentions files passed to `--settings`, the only mention of that flag found in the official pages reviewed |
| [Install and authenticate](https://antigravity.google/docs/install?tab=cli) | Native cached CLI credentials, provider overrides, and the separately documented SDK authentication path |
| [SDK overview](https://antigravity.google/docs/sdk/overview) | Reviewed to avoid conflating the Python SDK API with account-backed CLI execution |
| [SDK policies](https://antigravity.google/docs/sdk/policies/) | SDK policy functions are not passed to or advertised as CLI flags |
| [SDK lifecycle](https://antigravity.google/docs/sdk/lifecycle/) | Separate SDK session contract; not transplanted into the CLI adapter |
| [Claude plugin manifest](https://code.claude.com/docs/en/plugins/manifest-reference) | Plugin manifest, conventional component directories, plugin-relative scripts |
| [Claude marketplace creation](https://code.claude.com/docs/en/plugins/create-marketplace) | GitHub marketplace registration, plugin installation, version-pinned updates |
| [Claude skills](https://code.claude.com/docs/en/skills) | Turn-scoped `allowed-tools` pre-approval of the runner command |

Architecture references: [Codex Council](https://github.com/ehzawad/codex-council) and [Cursor Cult](https://github.com/ehzawad/cursor-cult). Their source was inspected through the connected GitHub account. The new plugin uses its own runtime modules and Antigravity protocol implementation; it does not assume the original projects' vendor flags transfer. The forced self-verification turn draws on two DeepSeek research sources, cited with what they contributed in [RECONCILIATION.md](RECONCILIATION.md); nothing is copied from them.

A force-permission default is now asserted for full roles, the 1.0.0 default: `--dangerously-skip-permissions`, `--mode accept-edits`, and session-only `--settings`, checked on every run through `init.permission_mode`. `--settings` appears in the installed `agy --help` and the 1.5.8 changelog but not in the official flag table. The runner requires it at preflight, and it was verified live on agy 1.5.12. The tools visible to full workers (with `inheritMcp`'s effect unproven), the browser-tool refusal, the tool-name mapping, the per-turn `init`/`result` pattern the two-turn run relies on, per-turn `--print-timeout`, and the refusal of `--effort` beside a catalog variant ID are likewise live observations on 1.5.12, not documented contracts. No undocumented SDK account transport, metadata JSON flag, or unlimited native timeout value is asserted. Code, tests, and docs record intentional assumptions and local verification gaps.
